# WWCPPOIConformanceTests

Conformance suite for WWCP POI 3, holding two implementations to one set of golden vectors: WWCP_POI3 (C#,
`libs/WWCP_POI`, also the home of `SPECIFICATION.md`) and WWCP_POI.TS (TypeScript, `libs/WWCP_POI.TS`).

## Orientation

- **The specification is `libs/WWCP_POI/SPECIFICATION.md`** (submodule); the canonical JSON and CBOR are specified in
  `libs/Styx/Styx/Illias/JSON/README.md`. This repository holds only vectors, harnesses and analysis.
- **The vectors:** `test-vectors/poi-*.json` are GENERATED by `tools/generate-test-vectors.mjs` - edit the generator,
  rerun it, never the JSON. It takes every value verbatim from its source (drift guard), re-derives the anchors with
  `node:crypto` and refuses to write on a mismatch; `--check` is the CI guard. The format is in
  `test-vectors/README.md`.
- **The frozen run** `test-vectors/runs/csharp-987fa26/` is what the C# examples A1 to A13 and MakeProofs of WWCP_POI
  `987fa26` published. Every run of the examples makes new keys: it is frozen, not regenerated - replaced only when the
  specification changes what a run publishes (`987fa26`: hardware revisions and firmware versions, certificates for
  station and meter models with their components, `csharp-80e4ccc` before with new values given as the content holds
  them, `csharp-bc3b1bd` before with change sets identified by their content, `csharp-dbf39b0` before with the digests
  of price statements, `csharp-801bbce` before that).
- **WWCP_POI.TS vendors everything** in `tests/vectors` (the run as `csharp-987fa26`, next to the `poi-*.json`) and runs
  the golden vectors in its own suite, `tests/conformance.test.ts` with its loader `tests/conformance.ts`.
  `VendoredCopiesTests` fails on drift; `--mirror libs/WWCP_POI.TS/tests/vectors` refreshes the copy. A change of the
  vector FORMAT therefore touches three harnesses: the C# one and the TS one here, and `tests/conformance.ts` there.
- **The trust vectors** (`poi-trust.json`) are signed by the generator with the Ed25519 seeds of SPECIFICATION.md
  section 6 (and two of its own) - deterministic, so regenerating changes no byte unless the generator changes.
- **The histories the generator signs** (`poi-histories.json`, its section 7) are where a vector needs a history signed
  anew, which the private keys of the frozen run do not allow: small histories of `rn1`, keys of the seeds of section 6
  and of its own (Ed25519, Ed448, ES256 after RFC 6979), its own small applier for the after ETags, and replays,
  every refusal with its `control`. What it calculates (CBOR, the effective tree, identifications, signature inputs) it
  anchors on the frozen run first. Its effective content is the content: no templates or tariffs in those histories.
- **What the implementations get wrong:** `docs/implementation-deviations.md`. Each deviation is in `DEVIATIONS` of the
  generator, marked on its vectors (`knownDeviations`, `deviation` anchor) and pinned: the harness of the deviating
  implementation expects the deviation, so a fix turns it red. Fixing one means: remove it from `DEVIATIONS`,
  regenerate, update the document.
- **What WWCP_POI.TS found reading the C# code:** `docs/csharp-review.md`, cited as *csharp-review N* (in vectors,
  the deviations, WWCP_POI.TS and the tests of WWCP_POI); fixed findings are marked ✅. It moved here from `docs/` of
  WWCP_POI.TS, which keeps a stub there.
- The C# harness reads JSON through WWCP_POI3's internal `POIJSON.Read`, by reflection (`VectorFiles.cs`,
  `POIJSONReader`): as the implementation reads what it hashes. If it goes away, adapt the harness, do not fall back
  to plain Newtonsoft (which is lenient, see D1).

## Build & test

```
git submodule update --init --recursive
dotnet test WWCPPOIConformanceTests.slnx
npm --prefix Tests/WWCPPOIConformance_Tests.TS install
npm --prefix libs/WWCP_POI.TS ci
npm --prefix Tests/WWCPPOIConformance_Tests.TS test
node tools/generate-test-vectors.mjs --check
```

The TS harness imports WWCP_POI.TS from source, so the implementation's own dependencies must be installed too
(resolved from `libs/WWCP_POI.TS/node_modules`); without it, `ERR_MODULE_NOT_FOUND` before a single vector.

Expected: C# 361 passed (its 7 copy tests need the vendored `poi-*.json` of WWCP_POI.TS, or are skipped), TS 328
passed / 20 skipped (7 signing: WWCP_POI.TS verifies only; 13 replays of `poi-histories.json` that WWCP_POI.TS leaves
to WWCP_POI: references, provider groups, grid connection points). Skips are load-bearing, not noise.

## Ground rules

- **Neither the implementations nor the specification are here.** Changes to POI code belong in WWCP_POI /
  WWCP_POI.TS, changes to the specification in WWCP_POI. This repository holds vectors, harnesses and the analysis.
- New vectors: add to the generator with a fresh id (never reuse one), regenerate, make sure BOTH harnesses run them
  (or mark `requires` / `notApplicable` deliberately). A vector enters only when two implementations agree on it, or
  carries the `knownDeviations` of the one that does not.
- A refusal vector must change what it claims to change: the harnesses check the unpatched document first (control),
  and the generator refuses a patch that changes nothing. A refusal for the wrong reason (e.g. a time before the key
  statement instead of before the attestation) proves nothing - look at the error message both give, and where both
  word it alike, name it in the vector's `reason`, which both harnesses check.
- `libs/Directory.Build.props` shields the submodules from this repository's build settings - keep it.
- CI gates the pinned submodules; `nightly.yml` advances all four to upstream HEADs (`branch = master` in
  `.gitmodules`) and runs the C# examples of WWCP_POI master against WWCP_POI.TS (informational).
- Commands handed to the user are Windows PowerShell 5.1: no `&&`, Windows paths, tool directory flags
  (`npm --prefix`, `git -C`) instead of `cd`.
